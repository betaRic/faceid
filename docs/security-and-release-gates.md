# Security and Release Gates

## Preserved security decisions

- Shared Regional Admin PIN and named Admin/HR PIN access remain supported.
- PIN login is server-verified, rate-limited, collision-blocked, audited, and converted to signed staff-session cookies.
- Regional PIN enablement is stored explicitly; missing or malformed control state fails closed.
- Office-scoped sessions cannot cross office boundaries.
- Office HR cannot read or mutate map, GPS coordinates, or geofence radius.
- Public registration remains pending until authorized review.
- Existing employees cannot overwrite their identity or biometrics through public registration.
- Attendance identity uses access-code claim plus face verification; employee ID is display/HR data, not the attendance primary key.
- Destructive biometric reset is removed. Controlled re-enrollment remains authorized and audited.

## Biometric trust limits

Attendance and enrollment descriptors are generated by the server from submitted still frames. This is stronger than accepting browser descriptors. It does not prove camera authenticity, location authenticity, or independently calibrated anti-spoof performance because frames, GPS, and temporal liveness evidence still originate in the browser.

OpenVINO is not the active matching authority. A model switch requires measured field evidence, preservation proof, shadow comparison, rollback, and explicit approval. Mass re-enrollment is not an acceptable default response to uncertainty.

## Required automated gates

```powershell
npm test
npm run test:routes
npm run build:hosting
git diff --check
```

The isolated route suite must cover registration approval, duplicate block/review, kiosk accept/reject, Office HR scope, lifecycle changes, attendance correction, DTR output, and cron authorization. Passing unit tests alone is not release proof.

## Required workflow gates

- Public registration succeeds and appears under pending review.
- Existing employee re-registration is blocked without altering stored data.
- Admin/HR can activate, reject, deactivate, and return an employee to review within scope.
- Kiosk accepts a valid access-code/face/policy/location case and rejects mismatch, pending, inactive, replay, invalid challenge, and out-of-policy cases.
- Office HR can manage permitted workforce settings but cannot see or submit location/radius fields.
- Current office/division filters enforce ownership. A future department/division/section release must add and verify the missing schema and cascading behavior before claiming that hierarchy is supported.
- Attendance correction display, summary, export, and DTR agree through the canonical daily derivation.
- Mobile registration, scan, employee review, filters, modal scrolling, keyboard access, reduced motion, and smooth scrolling are verified in a real browser.

## Production gate

Before production change, require:

1. a fresh restorable PostgreSQL 18 custom-format backup and hash;
2. exact migration list and preservation fingerprints;
3. passing automated and workflow evidence from isolated/local databases;
4. successful Node 22 hosting build with `.next/BUILD_ID`;
5. exact upload list, rollback steps, and known-risk list; and
6. separate operator approval.

No local cleanup, test, or build result is itself deployment authorization.
